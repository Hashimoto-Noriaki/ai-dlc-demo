# Extensions フェーズ

## 目的

既存のシステムが安定稼働している状態で、ドメインを拡張・成長させる。

- 新しい Bounded Context を追加する
- 既存コンテキストに新機能を安全に追加する
- コンテキスト間の連携を強化する
- 技術負債を計画的に解消する

## Construction との違い

| 観点 | Construction | Extensions |
|------|-------------|------------|
| スコープ | MVP の実装 | ドメインの成長 |
| リスク | 新規作成が多い | 既存への影響を常に考慮 |
| テスト戦略 | 新規テスト作成 | リグレッションテストが最重要 |
| デプロイ | 機能単位 | マイグレーションとの調整が必要 |

## Extensions のトリガー

以下のいずれかが発生したとき Extensions 作業を開始する:

1. 新しい Bounded Context の追加が決まった
2. 既存コンテキストに大きな機能追加がある
3. コンテキスト間の連携方式を変更する
4. スケールのためのリファクタリング

## 主な成果物

| 成果物 | 担当 | 保存先 |
|--------|------|--------|
| 新コンテキストの Context Card | AI + 人間 | `docs/domain/` |
| マイグレーション計画 | 人間 + AI | `docs/migrations/` |
| ADR (変更の場合) | 人間 + AI | `docs/adr/` |
| API 変更ログ | AI 自動生成 | `CHANGELOG.md` |
