# ドメイン発見ルール (Inception)

## Event Storming with AI

### ステップ

1. **ドメインイベントの列挙**
   - プロンプト: `このシステムで起きる業務イベントをすべてオレンジ付箋形式で列挙してください`
   - 出力形式: `[過去形の動詞]された/された` (例: `請求書が作成された`)

2. **コマンドの抽出**
   - プロンプト: `各イベントを引き起こすコマンドを青付箋形式で対応させてください`

3. **集約の特定**
   - プロンプト: `コマンドとイベントをグループ化し、集約を黄付箋で定義してください`

4. **Bounded Context の境界を引く**
   - プロンプト: `集約をビジネス上のまとまりで囲み、各コンテキストに名前をつけてください`

5. **Context Map の作成**
   - コンテキスト間の関係 (Upstream/Downstream, ACL, OHS, PL) を定義

## Bounded Context 分割基準

```
✅ 分割する
- チーム・デプロイ単位が異なる
- 同じ言葉が別の意味を持つ (例: 「顧客」が請求側と会計側で違う)
- ライフサイクルが独立している

❌ 分割しない
- まだ1機能しかない
- 常に同じトランザクションで更新される
```

## 用語集 (Ubiquitous Language) ルール

- ドメインエキスパートの言葉をそのままコードに使う
- 英語名は日本語ドメイン語の直訳ではなく、業界標準英語を使う
- 用語が変わったらコードも変える (リネームを恐れない)

## 成果物テンプレート

### Bounded Context カード

```markdown
## Context: [名前]

**目的**: [このコンテキストが解決するビジネス課題]

**主な集約**:
- [集約名]: [役割]

**外部依存**:
- Upstream: [依存元コンテキスト] → [取り込み方法: ACL/Conformist]
- Downstream: [依存先コンテキスト]

**公開インターフェース**:
- [イベント名]: [内容]
```
